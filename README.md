# 我的工具箱 · 静态导航站

纯 HTML + CSS + 原生 JS，**不需要 Node、不需要构建、不需要服务器**，直接放 GitHub Pages 就能用。

## 文件说明

| 文件 | 作用 | 要不要改 |
|---|---|---|
| `index.html` | 页面骨架（吸顶导航、轮播、分页、弹窗容器） | 基本不用改 |
| `tools.js` | **所有工具数据 + 图片 + 轮播 + 底部四卡文案** | ✅ 只改这个 |
| `app.js` | 渲染、筛选、搜索、分页、弹窗逻辑 | 不用改 |
| `style.css` | 样式（配色、卡片、分页、弹窗） | 想换配色才改 |

## 功能

- **吸顶导航栏**：滚动页面时永远停在顶端，带毛玻璃模糊；往下滚会自动加阴影和底边线
  - 左侧站点名 + 中间分类导航 + 右侧搜索框和主题按钮
  - 手机上分类自动换行到第二行，可横向滑动
  - **站点名显示在导航栏**，页面主体不再有顶部横幅，内容直接开始
- **白天 / 黑夜切换**：右上角按钮，☀️ / 🌙 一键切换
  - 自动记住选择（localStorage）
  - 没手动选过就跟随系统深浅色，并实时响应系统变化
- **顶部轮播**：自动播放（4.5 秒切换），左右箭头 + 底部指示点，鼠标悬停暂停，点击可跳转
- 分类标签切换
- **更新动态横条**：自动读取工具数据按日期倒序生成，不用另外维护，点击可打开对应弹窗
- 卡片网格，悬停有上浮效果
  - **横向卡片：缩略图在左，文字在右**（长方形圆角）
  - 默认 **2 列 × 6 行 = 每页 12 个**，手机 1 列
  - 卡片用 `<article>` 语义标签，分类用 `<nav>`，主体包在 `<main>` / `<section>` 里
- 顶部搜索（名称 / 简介 / 详情 / 分类 全匹配）
- **分页**：上一页下一页 + 页码 + 省略号 + 跳页输入框，翻页后自动回到顶部
- 点击卡片弹出领取弹窗：版本 / 更新时间 / 平台图标 / 提取码一键复制 / 领取按钮
- **底部四张卡片**：关于工具箱 · 反馈与建议 · 免责声明 · 投稿推荐，点击分别弹窗
  - 反馈 / 免责 / 投稿 三个弹窗底部带联系邮箱和复制按钮
- 弹窗支持点遮罩关闭、按 Esc 关闭、右上角 ✕ 关闭

## 视觉优化（参考同类站点 CSS 提取的设计特征）

从同类导航站的 CSS 里提取了几个可复用的设计手法，已应用到本项目：

| 手法 | 说明 |
|---|---|
| **复合背景** | `radial-gradient` 光晕 + `linear-gradient` 底色叠加，不是纯色平铺 |
| **纸墨色阶** | 深色用蓝黑 `#0a1017`、浅色用柔白 `#f6f3ee`，避开纯黑纯白 |
| **极低透明度阴影** | `0 24px 48px #00000047`——透明度低、扩散大，比纯 rgba 更柔和 |
| **内高光** | 卡片/缩略图顶部一道 `inset 0 1px 0 #ffffff14`，立体感的关键 |
| **缩略图独立成盒** | 图片不贴边铺满，自带圆角/边框/阴影，像一张独立的小卡片 |
| **固定卡片高度** | 150px，列表整齐不参差 |
| **分类色调** | 四个分类四种渐变底色（AI暖橙蓝/工具蓝绿/创业紫棕/素材黄绿） |
| **View Transitions** | 主题切换时从按钮位置圆形扩散揭示（支持 `prefers-reduced-motion`） |

这些都是通用的 CSS 写法，不涉及具体内容。

## 性能与无障碍（参考同类站点 JS 提取的实现思路）

从同类导航站的 JS 里读到了几个实用的工程做法，已用原生 JS 实现：

| 做法 | 说明 |
|---|---|
| **IntersectionObserver 懒加载** | 图片进入视口附近才加载。预加载距离随「省流量模式」自动收缩：正常 360px，开启省流量后 160px |
| **空闲时预热** | 用 `requestIdleCallback` 在浏览器空闲时预载后 2 张图，滚动/翻页不白屏；不支持时降级为 `setTimeout` |
| **图片失败兜底** | 加载失败自动换成带名称的占位图，不留破图图标 |
| **骨架屏** | 首屏先画占位卡片（微光扫过动画），数据就绪后替换，杜绝白屏 |
| **首屏遮罩** | 页面渲染前用一层纯色遮罩盖住，避免深色/浅色切换时闪一下 |
| **主题预置** | 在 `<head>` 里同步读 localStorage 定好深浅色，不等 JS 主流程 |
| **焦点陷阱** | 弹窗打开后 Tab 键在弹窗内循环，不会跑到背景页面；关闭后焦点还给原卡片 |
| **滚动锁补白** | 锁滚动时补 `padding-right`，避免滚动条消失导致页面横向跳动 |
| **键盘可达** | 卡片和底部卡片都能 Tab 聚焦 + Enter/空格打开；有 skip-link 可跳过导航 |
| **preconnect** | 提前与图标服务握手，加快首屏图片 |
| **尊重减少动效** | 系统开了「减少动效」时，主题切换动画和骨架动画自动关闭 |

### 标题上沿与图片上沿齐平

- 缩略图 `align-self: stretch` —— 撑满卡片内容区高度，上下沿与右侧齐平
- `.card .body` 用 `flex-direction: column` + `align-items: stretch`
- 标题 `margin-top: -2px` + `line-height: 1.25`，抵消字体行高的半行距，
  让文字上沿**真正**贴合图片上沿（不是大致对齐）
- 标题**单行截断**，名字过长不会换行破坏对齐

> **别给 `.card .body` 加 `overflow: hidden`** —— 会把标题的负 margin 裁掉。
> 也别把 `align-items` 改成 `flex-start` —— 日期就贴不到右边了。

### 日期在右上角

`.card-head` 用 `justify-content: space-between`，标题 `flex: 1 1 auto` 占满剩余宽度，
日期 `flex: 0 0 auto` 被推到最右。日期同样加 `-2px` 负 margin 补偿行高，保证上沿齐平。

右上角显示**短格式**（`09-16`），鼠标悬停 `title` 显示完整日期（`2026-09-16`）。

### 简介响应式（照参考站的做法）

**屏幕窄就隐藏，拉宽就出现**——分四档：

| 屏幕宽度 | 简介 | 卡片高度 |
|---|---|---|
| ≥ 861px（桌面宽屏） | **显示 2 行** | 150px |
| ≤ 860px（平板 / 大手机横屏） | 显示 1 行 | 132px |
| ≤ 640px（手机） | **隐藏** | 104px |
| ≤ 380px（小屏） | 隐藏 | 96px |

## 主题切换（无闪屏）

点击右上角 ☀️/🌙 切换白天/黑夜。为避免闪屏做了三件事：

**① 不用 View Transitions**

早期版本用 `document.startViewTransition()` 做圆形扩散动画，但它要截取**整页快照**，
在移动端/低端设备上容易白闪、掉帧。现在改成：

```js
root.classList.add('theme-switching');   // 挂上临时 class
paint(t);                                // 切换主题
setTimeout(() => root.classList.remove('theme-switching'), 320);
```

配合 CSS `html.theme-switching *` 只在这 280ms 内让颜色过渡，结束后立刻摘掉，
**不影响 hover、弹窗等其它动画**。系统开了「减少动效」时直接瞬切。

**② 主题预置脚本放在 `<head>` 最前面**

必须在**任何 CSS 渲染之前**执行，否则首屏会先画深色、再跳成浅色——
这就是很多人感觉「打开时闪一下」的真正来源。

**③ 背景渐变挂在 `body::before` 固定伪元素上**

不用 `background-attachment: fixed`——它在 iOS Safari 上有已知的重绘闪烁问题，
切换主题时尤其明显。fixed 伪元素更稳，性能也更好。

## 吸顶导航 + 侧边栏跟随滚动

顶部导航和左侧分类栏都是 `position: sticky`，滚动时跟随。

### ⚠️ 一个坑：别用 `overflow-x: hidden`

之前全局写了：

```css
html, body { overflow-x: hidden; }   /* ❌ 会让所有 sticky 失效 */
```

`overflow-x: hidden` 会把 html/body 变成**滚动容器**，导致内部所有
`position: sticky`（吸顶导航、侧边栏）**全部失效**——表现为滚动时不跟随。

正确写法：

```css
html, body { overflow-x: clip; }     /* ✅ 同样裁横向溢出，但破坏 sticky */
```

`clip` 不会创建滚动容器。这是「加了防横向溢出后 sticky 突然不动了」最常见的原因。

### sticky 生效的必要条件

1. 祖先链（html → body → main → .app-shell）**不能有** `overflow: hidden/auto/scroll`
2. 侧边栏的 grid 父容器要 `align-items: start`（若是 `stretch`，侧栏会被拉满高度，sticky 无效）
3. 元素自身要有 `top` 值

### 侧边栏定位

`top: calc(var(--header-h) + 12px)` —— 贴在吸顶导航下方。
`--header-h` 由 JS 实测写入（header 高度会随分类换行变化，写死会错位）。

侧栏还加了 `max-height: calc(100vh - var(--header-h) - 24px)` + `overflow-y: auto`，
分类多到超出一屏时**侧栏内部滚动**，而不是把页面撑长。窄屏抽屉下取消这个限制。

### 悬浮但不遮挡

- `sticky` 在文档流中**占位**，本身不覆盖内容（和 `fixed` 不同）
- 滚动后 header 变实色 + 双层阴影（贴近的细阴影 + 扩散柔光），层次更自然
- 加了 `scroll-margin-top`，锚点跳转（如 skip-link「跳到主内容」）时不会被吸顶导航盖住

## 工具箱动态（自动轮播切换）

不是固定显示几条，而是**一条一条自动切换**：每 3.6 秒淡入 + 从下往上滑入下一条。

## 图标：本地优先 + 国内源兜底

### ⚠️ 一个关键认知

**服务器在哪，不影响图标加载速度。**

图标是**浏览器直连图源**请求的，不经过你的服务器。所以：

- 站放国内服务器 → 访客在国内 → 浏览器请求境外图源 → **照样慢**
- 站放 GitHub Pages → 访客在国内 → 同样是浏览器请求 → **一样慢**

**决定速度的是访客在哪，不是服务器在哪。** 两个站都需要国内源兜底。

### 图源顺序（自动）

```
本地 ico/域名.png          ← ① 最快最稳，不依赖网络
  ↓ 失败
api.iowen.cn（国内）       ← ② 一为，专门给导航站做的
  ↓ 失败
favicon.im（境外）         ← ③ 兜底
  ↓ 失败
icons.duckduckgo.com       ← ④ 境外备用
  ↓ 全失败
占位图（带站点名的渐变图）  ← 不会留破图
```

每级都有 **4 秒超时**（国内访问境外可能一直挂着不返回）和
**尺寸校验**（防止图源返回 1×1 透明图冒充成功）。

### 最稳方案：把图标本地化

用随包附带的 `下载图标.py`，批量下载所有站点图标：

```bash
python3 下载图标.py tools.js       # 资源工具箱
python3 下载图标.py index.html     # 导航站
```

会生成 `ico/` 目录，命名成「域名.png」。上传整个目录后，
**图标全部走本地文件，不再请求任何外部图源**——不管访客在哪都秒开。

下载失败的站点，手动存一张到 `ico/域名.png` 即可（脚本已支持跳过已存在的）。

### 手填图标

`tools.js` 里给某条数据填 `icon: 'images/xxx.png'`，
就会**直接用它，跳过所有多源探测**。

### subCats 加在哪里

**加在 `tools.js` 的 `var SITE = { ... }` 里面**，位置随意（我放在 `pageSize` 下面）。

关键是：

1. 必须在 `var SITE = {` 和它对应的 `}` **之间**

### 宽度要和「工具箱动态」对齐（已修复）

#### 现象

手机上「工具箱动态」和下面的二级模块**不一样宽**。

#### 根因

右列（`.content`）内的区块有一条统一规则：

```css
/* 宽度由 .app-shell 统一管理，右列内部区块左右 padding 一律归零 */
.content .newsbar { padding: 0 0 4px; }
```

`newsbar` 被归零了，但 **`subbar` 没加进这条规则**，它自己还带着
`padding: 10px 20px`（桌面）/ `8px 14px`（手机）。

于是两者左右各差 14~20px，合计差 **28~40px** —— 看起来就是上下两个模块不对齐。

（不只是手机端，桌面端其实也差，只是不明显。）

#### 修复

把 `subbar` 纳入同一组规则：

```css
.content .newsbar,
.content .subbar { max-width: 100%; }

.content .newsbar { padding: 0 0 4px; }
.content .subbar  { padding: 8px 0 2px; }   /* 只保留上下间距 */
```

#### 记住这条规则

**右列内新增任何区块，左右 padding 都要归零**，
宽度交给 `.app-shell` 统一管。否则就会和上下邻居对不齐。

## 单网盘徽章文字溢出外框（已修复）

### 现象

单个网盘的徽章圆角框**没包住文字**，文字撑到框外。多网盘正常。

### 根因：后代选择器污染

```css
/* ❌ 后代选择器：空格，会匹配任意层级 */
.modal .row span:first-child { width: 72px; flex: 0 0 72px; }
```

单网盘的 DOM：

```html
<div class="row pan-row">
  <span>网盘</span>                 ← 第 1 个 span，72px（预期）
  <span class="pan-list">
    <span class="pan-badge">        ← .pan-list 的第 1 个也是唯一子元素
```

`.pan-badge` 是 `.pan-list` 的 `span:first-child`，**被这条规则命中 → 强制 72px**。

但徽章实际需要约 94px（图标 20 + 间距 6 + 文字 + 内边距），
又有 `white-space: nowrap` 不换行 → **文字撑出圆角外框**。

DevTools 里会看到 `span.pan-list` 也是 72px——因为 pan-list 的宽度
由内容（被压成 72px 的 badge）决定，跟着一起窄了。

**多网盘为什么正常**：那边渲染的是 `<button>` 不是 `<span>`，
根本不匹配这条规则。

### 修复

```css
/* ✅ 用 > 限定直接子元素，再用 :not 排除 pan-list */
.modal .row > span:first-child:not(.pan-list) { width: 72px; flex: 0 0 72px; }
.modal .row > span:last-child:not(.pan-list)  { color: var(--text); word-break: break-all; }

/* 双保险：徽章永远不被压缩 */
.modal .pan-badge { flex: 0 0 auto; width: auto; white-space: nowrap; }
```

### 教训

**布局类选择器尽量用 `>` 限定层级**。

后代选择器 + `:first-child` / `:last-child` 组合非常容易污染嵌套结构——
只要内部某层恰好是父元素的唯一子元素，就会被误命中。

## 底部四张卡片：为什么原来会错位

### 现象

四张卡片（关于 / 反馈 / 免责 / 投稿）排成了 **3 + 1**，不是整齐一行。

### 真正原因（和页脚无关）

页脚 `<footer>` 在 `</main>` **外面**，DOM 上是独立模块，不会影响卡片。

问题是**宽度不够**：

```
内容宽度 1200px
− shell 内边距 40px
− 侧边栏 232px
− 间距 20px
─────────────────
右列实际宽度 = 908px

四张卡需要：4 × 230px + 3 × 14px = 962px  >  908px  → 放不下！
```

原来的 `grid-template-columns: repeat(auto-fit, minmax(230px, 1fr))`
在 908px 下只能放下 3 个，第 4 个就换行了。

### 修复

改成**强制 4 等分**，允许压缩：

```css
.content .foot-cards {
    grid-template-columns: repeat(4, minmax(0, 1fr));
}
```

`minmax(0, 1fr)` 里的 `0` 是关键——表示这一列**允许被压缩**，
不会像 `minmax(230px, ...)` 那样撑破容器。每列约 216px。

窄屏降级（文件末尾统一收口）：

| 视口 | 列数 |
|---|---|
| ≥1100px | 4 列 |
| ≤1099px | 2 列 |
| ≤640px | 2 列 |
| ≤380px | 1 列 |

### ⚠️ 一个 CSS 坑（改的时候要注意）

`.content .foot-cards` 特异性是 **(0,2,0)**，
比 media query 里的 `.foot-cards` **(0,1,0)** 高。

所以写在 media 里的降级规则**会被基础规则覆盖掉**，窄屏降级失效。

解决办法：降级规则也用 `.content .foot-cards`（同样特异性），
并且**写在基础规则之后**。相关代码统一放在 `style.css` 文件末尾
的「布局收口」区块里，改列数去那里改。

### 另一个坑：类名撞车

页脚的版权行原本也叫 `.f-copy`，和四卡里的文字区 `.f-copy` 同名，
导致版权行的 `opacity: .7; font-size: 11.5px` 污染了四卡文字。

现在页脚版权行改名为 `.f-copyright`。

```js
    icp:    '鲁ICP备xxxxxxxx号-x',          // 备案号（留空不显示）
    icpLink:'https://beian.miit.gov.cn',    // 工信部查询地址，一般不用改
    ga:     '',                             // 公安备案号（可选）
    gaLink: 'https://www.beian.gov.cn',
    links: [                                // 额外链接，可加多个
        { text: '版权反馈', url: 'mailto:your-email@qq.com' }
    ],
    copyright: ''                           // 例：'© 2026 我的工具箱'
}
```

### ⚠️ 备案号必须填你自己的

国内服务器上的站点，**底部展示备案号是合规要求**。

你截图里那个 `鲁ICP备2024081540号-2` 是**别人站的备案号**，
**不能直接抄**——备案号对应备案主体，填错了等于挂别人的备案信息，
被核查到会有麻烦。

填你自己备案下来的那个号。没备案就先留空（`icp: ''`），
这一行会自动不显示，不影响其他功能。

### 细节

- 备案号用**实线下划线**（比虚线更正式），其余链接用虚线，hover 变品牌色
- 站点名稍亮、说明稍淡，拉开层次
- `mailto:` 链接**不加** `target="_blank"`（邮箱不该开新标签）
- 外链都带 `rel="noopener"`，安全
- 刘海屏 / home indicator 做了 `safe-area-inset` 避让
- 没填备案号、没填链接时，对应行自动不渲染，不留空行

## 动图（gif / webp）怎么加到缩略图

**能加**——缩略图就是普通 `<img>`，gif / webp 动图都直接支持。

但要**注意体积**：动图动辄几 MB，而一屏有 12 张卡片。
如果全都用动图，首屏要下载几十 MB，页面会卡死。

### 推荐做法：悬停才播放

我加了 `thumbAnim` 字段——**静图常显，鼠标移上去才加载动图**：

```js
{
    id: 1,
    name: 'Cap 开源录屏',
    thumb:     'images/cap.jpg',        // 静图：首屏加载，几十 KB
    thumbAnim: 'images/cap-anim.gif',   // 动图：鼠标移上去才下载
    ...
}
```

好处：

- **首屏零负担**——动图完全不参与首屏加载
- 只有用户真正感兴趣（把鼠标移上去）才下载
- 移开还原静图，来回切换用的是浏览器缓存，第二次就秒切
- 鼠标移动时先偷偷预载，下载完再换 src，**不会出现半张图或空白**

### 文件怎么放

1. 在网站根目录建个 `images/`（或 `ico/` 等，随意）
2. 把动图放进去，比如 `images/cap-anim.gif`
3. 在 `tools.js` 里填相对路径：`thumbAnim: 'images/cap-anim.gif'`

示例包里已经放了一个 `images/demo-anim.gif`（6 帧，68KB）
并挂在第 1 条数据上，可以直接看效果。

### 动图制作建议

| 项 | 建议 |
|---|---|
| 尺寸 | 320×240 就够（卡片就这么大，做大了浪费） |
| 帧数 | 6~12 帧足够，太多只增体积 |
| 体积 | **≤ 500KB**（超过就首屏卡） |
| 格式 | **WebP 动图比 GIF 小 60~80%**，优先用 WebP |
| 压缩 | ezgif.com 可在线压缩/裁剪/改帧率（免费） |

### 手机端

手机没有 hover，所以改成**点一下切换**成动图（已在代码里处理）。
不过更推荐的做法是：手机端干脆只用静图——毕竟移动端流量更宝贵。

### 直接把动图当 thumb 也行

如果某张动图很小（比如 100KB 以内），也可以直接：

```js
thumb: 'images/xxx.gif',   // 不用 thumbAnim，直接播放
```

但**别给多张卡片都这么干**。

## 图片字段

| 字段 | 用途 | 建议尺寸 |
|---|---|---|
| `thumb` | **卡片缩略图** | 320×240 |
| `cover` | **弹窗大图** | 800×600 |

**两种用法：**

**① 只填 `thumb`**（最省事）
```js
thumb: 'images/cap.jpg',
cover: '',
```
卡片显示这张图，弹窗自动把同一张放大显示。**只需准备一套图。**

**② `thumb` + `cover` 都填**（效果最好）
```js
thumb: 'images/cap.jpg',        // 卡片小图，加载快
cover: 'images/cap-large.jpg',  // 弹窗大图，清晰
```
点开后弹窗显示大图，这就是你要的那种「小图 → 点开变大图」效果。

**两个都不填** → 自动生成一张带工具名的渐变占位图（320×240），
所以你还没准备图片时页面也不会难看。想关掉就把 `SITE.autoPlaceholder` 改成 `false`。

**改缩略图比例**：`SITE.thumbRatio`，默认 `'4 / 3'`（=320×240），
想改成 16:9 就写 `'16 / 9'`。

图片放仓库 `images/` 目录，先压缩（TinyPNG），仓库建议控制在 1GB 内。

## 部署到 GitHub Pages

1. 在 GitHub 新建仓库，比如叫 `my-toolbox`
2. 把这四个文件传到仓库根目录
3. 仓库 → **Settings** → **Pages** → Source 选 `Deploy from a branch`
4. Branch 选 `main`，文件夹选 `/ (root)`，点 Save
5. 等一两分钟，访问 `https://你的用户名.github.io/my-toolbox/`

以后改内容：编辑 `tools.js` → 提交 → 一两分钟后自动生效。

## ⚠️ 重要提醒

这个模板只是**交互效果和布局**的参考实现。请务必：
